### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then audit every worktree read-only (principle-build-the-lever). Read paths from `git worktree list --porcelain`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `~/.t3/worktrees/<repo>/<branch>` (principle-encode-lessons-in-structure). `t3_worktree_list` omits detached worktrees, so use it to cross-check T3's view, not to enumerate. Check `MERGED` with `git merge-base --is-ancestor <head> <base>` against the branch PRs target. Fetch that base first, and pass `origin/<branch>` when PRs target something other than `origin/HEAD`. Squash-merged branches are not ancestors of the base, so PR state from `gh pr list --state all` is the real signal. Classify each worktree by size, age, merge state, uncommitted work, unpushed commits, PR state, and the newest thread that touched it, then suggest a bucket. Match threads to worktrees by linked PR from `t3_thread_list` and by branch or path with `t3_thread_search`. The thread scan is slow, so hand it to a `delegate_task` worker with `mode: "async"`.
2. The bucket is advice, not permission. The open threads are the real artifact (principle-prove-it-works): unsettled ones, snoozed ones included, and anything running or waiting. Get that set from `t3_thread_list` with `settled: false`, the sidebar, and the user, and cross-check every candidate. The audit has marked `safe` a worktree the user still had open, so the user's set wins.
3. Verify usage before deleting. For every `verify-recent-thread` row, or anything you doubt, fan `delegate_task` workers out with self-contained briefs and `mode: "async"` to read the threads with `t3_thread_read` and `t3_thread_search` and report whether the thread is still open or ongoing and which worktrees it touches (principle-guard-the-context-window, threads are bulk). Drain with `task_status`. An open thread spawns arena and repro trees into sibling worktrees via `t3_thread_launch` and delegated tasks, and those are in use even when their names never hit the sidebar.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. Per Autonomy, clean and merged and not-in-use proceeds. `wip`, unpushed work, and in-use pause.
5. Prune the confirmed set. Per path, `git worktree remove --force <path>`. If the dir survives on ignored build artifacts, `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list with `git worktree list`.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. Enumerate with `device_list`, then `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which thread, or holding uncommitted or unpushed work).
